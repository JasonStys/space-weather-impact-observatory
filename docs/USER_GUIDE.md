# User guide and troubleshooting

By Jason Stys. Start with the README's download/source instructions. Use a reviewed source build if unsigned apps are blocked; never weaken OS protection. The local browser UI opens automatically; a console prints the exact loopback URL if the browser does not open. Stop Ctrl-C. No installer/service or auto-start entry is created.

1. **Choose the evidence source.** NOAA frozen snapshot is seven days of estimated planetary Kp and unknown-issue future forecasts. It intentionally has no health or scores. Other cases are visibly invented; the storm-shaped case is not a reconstruction of a real storm.
2. **Choose an analytical threshold.** 4/5/6 changes event bins and the score confusion table, not the weather values. It is not a physical safety limit or a NOAA scale label.
3. **Set positive health lag.** Weather at t joins health at t+lag. Inspect a bin to see both exact times; trailing health outside the grid remains unavailable. Comparing many lags can create selection bias; the app does not pick the best one.
4. **Set minimum forecast lead.** In the revision case, compare 3, 12 and 24 hours. A later, worse forecast can be selected if it is the latest eligible revision. Expand the forecast ledger to see all exclusions and errors. Unknown issuance never becomes trustworthy because it was downloaded.
5. **Read missingness.** Crosses are missing, not zero. `Not available` on Pearson r can mean <3 pairs or constant signals; the reason is shown. Group means are only descriptive. Weather and count charts have separate units/scales.
6. **Inspect and filter.** Every bin button opens its exact context. Missing/event/paired filters affect the visible ledger only, not full-window metrics/downloads. Chart and ledger regions support keyboard focus and horizontal scrolling on narrow screens; numeric values are in the ledger.
7. **Export the context.** JSON/HTML preserve all data, settings, eligibility reasons and limitations; CSV is the aligned-bin table; input JSON can be edited for explicit CLI-only analysis. A SHA identifies content, not who supplied it. Import example: `python -m weatherlab export --input examples/synthetic-storm.json --output review.json`.
8. **Preferences and privacy.** Remember settings is off by default. When enabled, only the four finite selectors are saved in localStorage, not private records; unchecking removes the preference. Local input/history is not served over HTTP. This is unencrypted local storage, not protection from someone controlling your OS/browser profile.

If evidence fails, stale results/downloads are hidden and Try again appears. Verify the build and snapshot files; do not replace a failed NOAA snapshot with synthetic observations or disable checksum checks. Source startup needs `npm ci` and `npm run build`. Use `--no-browser` to suppress opening, `--port` to choose another free local port. Port collisions/permissions are reported, not fixed by elevating the app. An invalid import prints a controlled error; fix the schema rather than guessing timezone/units. Existing export destinations are never overwritten; choose a fresh path. History full means choose a new explicit local path, not auto-prune old results.
